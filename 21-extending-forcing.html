23 Adding a new forcing

Most extensions to DriftScope are new terms in the master equation Eq. 5.2. This chapter walks through the end-to-end pattern for adding one, using a hypothetical internal-wave drift module as the worked example. By the end you’ll know which files to touch, which to leave alone, and how to verify the new term actually does something.

23.1 The four pieces

Every velocity-field forcing in DriftScope has the same four pieces:

  1. A fetcher — driftscope/<name>.py that downloads or computes the data and saves it as a NetCDF with (time, latitude, longitude) coordinates and named velocity components.
  2. A combine_forcings() clause — driftscope/simulate.py:47 adds the new field to the existing currents.
  3. A SimConfig flag — driftscope/config.py’s SimConfig dataclass adds an include_<name> boolean and any tuning parameters.
  4. A CLI flag — driftscope/simulate.py’s main() adds --<name> and --<param> arguments.

For a per-particle forcing (settling, Brownian) the pattern is slightly different — see Section 23.3 below.

23.2 Worked example: internal-wave drift

Internal waves at the pycnocline produce a small Stokes-drift-analog mean flow at the surface. Let’s add it.

23.2.1 Piece 1 — the fetcher

Create driftscope/internal_waves.py:

"""Internal-wave-induced surface drift.

Internal waves at the pycnocline shed surface trapped energy into a
weak (~1-2 cm/s) mean drift via wave–wave nonlinear interactions. Less
well-quantified than Stokes drift; we use a simple parameterization
based on the local mixed-layer depth and surface stratification.

Currently: a placeholder that computes uniform 1 cm/s eastward drift —
useful as a unit test for the new-forcing extension pattern.
"""
from __future__ import annotations
from datetime import datetime, timedelta, timezone
from pathlib import Path

import numpy as np
import xarray as xr
from rich.console import Console

from .config import IW_DIR  # add this to config.py

console = Console()


def output_path(region_name: str, start: str, end: str) -> Path:
    safe = region_name.lower().replace(" ", "_")
    return IW_DIR / f"{safe}_{start}_{end}_iw.nc"


def fetch_iw_drift(bbox, start_date, end_date,
                   currents_nc, region_name="custom", force=False):
    """Compute a placeholder uniform 1 cm/s eastward IW drift.

    For a real implementation, replace the body with a model query
    (e.g. Whalen et al. 2020 climatology) or a derivation from
    CMEMS T/S profiles.
    """
    out = output_path(region_name, start_date, end_date)
    if out.exists() and not force:
        console.print(f"[green]✓[/green] cached: {out.name}")
        return out

    cur = xr.open_dataset(currents_nc)
    lon_name = "longitude" if "longitude" in cur.coords else "lon"
    lat_name = "latitude" if "latitude" in cur.coords else "lat"

    # Match the currents grid for spatial coordinates; daily for time.
    times = cur["time"].values
    lons = cur[lon_name].values
    lats = cur[lat_name].values

    u_iw = np.full((len(times), len(lats), len(lons)), 0.01, dtype="float32")
    v_iw = np.zeros_like(u_iw)

    ds = xr.Dataset(
        data_vars={
            "u_iw": (("time", lat_name, lon_name), u_iw,
                     {"long_name": "Internal-wave drift, eastward",
                      "units": "m s-1"}),
            "v_iw": (("time", lat_name, lon_name), v_iw,
                     {"long_name": "Internal-wave drift, northward",
                      "units": "m s-1"}),
        },
        coords={"time": times, lat_name: lats, lon_name: lons},
    )
    ds.to_netcdf(out)
    console.print(f"[green]✓[/green] saved {out.name}")
    return out


def main():
    import argparse
    p = argparse.ArgumentParser(description="Compute IW-drift placeholder")
    p.add_argument("--bbox", required=True, type=str)
    p.add_argument("--start", required=True)
    p.add_argument("--end", required=True)
    p.add_argument("--region", default="custom")
    p.add_argument("--currents", required=True, type=Path)
    p.add_argument("--force", action="store_true")
    args = p.parse_args()
    bbox = tuple(float(x) for x in args.bbox.split(","))
    fetch_iw_drift(bbox, args.start, args.end, args.currents,
                   args.region, args.force)


if __name__ == "__main__":
    main()

23.2.2 Piece 2 — extend combine_forcings()

In driftscope/simulate.py:47, add the new clause to combine_forcings():

def combine_forcings(
    currents_nc, stokes_nc=None, tides_nc=None, winds_nc=None,
    iw_nc=None,                # NEW
    stokes_scale=1.0, windage_coeff=0.03,
):
    tag = []
    if stokes_nc:  tag.append(f"stokes{stokes_scale:.1f}")
    if tides_nc:   tag.append("tides")
    if winds_nc:   tag.append(f"wind{windage_coeff*100:.1f}pct")
    if iw_nc:      tag.append("iw")        # NEW
    suffix = ("__" + "_".join(tag)) if tag else "__currents_only"
    out = currents_nc.with_name(f"{currents_nc.stem}{suffix}.nc")

    inputs = [currents_nc] + [p for p in (stokes_nc, tides_nc, winds_nc, iw_nc)
                               if p is not None]
    # ... existing time-grid logic ...

    if iw_nc is not None:                  # NEW BLOCK
        iw = xr.open_dataset(iw_nc)
        iw_lon = "longitude" if "longitude" in iw.coords else "lon"
        iw_lat = "latitude" if "latitude" in iw.coords else "lat"
        u_iw = iw["u_iw"].interp(
            {iw_lon: cur[cur_lon], iw_lat: cur[cur_lat], "time": time_grid},
        ).fillna(0.0)
        v_iw = iw["v_iw"].interp(
            {iw_lon: cur[cur_lon], iw_lat: cur[cur_lat], "time": time_grid},
        ).fillna(0.0)
        uo = uo + u_iw
        vo = vo + v_iw

    combined = cur_resampled.copy()
    combined["uo"] = uo; combined["vo"] = vo
    combined.to_netcdf(out)
    return out

The pattern is identical to the existing Stokes/tides/winds blocks: open the file, interpolate to the currents grid+time, fill NaN with 0, add to uo/vo.

23.2.5 How to verify it works

# 1) Fetch the new field
python -m driftscope.internal_waves \
    --bbox 88,21,90.5,22.8 --start 2025-01-15 --end 2025-01-29 \
    --region sundarbans \
    --currents data/currents/sundarbans_2025-01-15_2025-01-29.nc

# 2) Run a baseline + IW simulation
python -m driftscope.simulate \
    --currents data/currents/sundarbans_2025-01-15_2025-01-29.nc

python -m driftscope.simulate \
    --currents data/currents/sundarbans_2025-01-15_2025-01-29.nc \
    --iw data/internal_waves/sundarbans_2025-01-15_2025-01-29_iw.nc

# 3) Compare day-10 mean positions
python -c "
from driftscope.viz import load_trajectories, traj_to_dataframe
for suffix in ['currents_only', 'iw']:
    ds = load_trajectories(f'data/trajectories/sundarbans_2025-01-15_2025-01-29__{suffix}_traj.zarr')
    df = traj_to_dataframe(ds)
    last = df.groupby('traj').tail(1)
    print(f'{suffix:15s}  mean ({last.lon.mean():.4f}E, {last.lat.mean():.4f}N)')
"

With a uniform 1 cm/s eastward drift over 10 days, particles should shift ~8.6 km east of the no-IW case. Verify the longitude differs by ~0.08° (\(\approx 8.6\) km / 111 km/°).

If yes: end-to-end pattern works. Replace the placeholder content in internal_waves.py with real physics.

23.3 Per-particle forcings — kernels

A per-particle forcing — different velocities for different particles at the same location — needs a kernel, not a field. Examples:

  • Settling (different sizes → different vertical velocities).
  • Reaction kinetics (a particle decays over time).
  • Buoyancy depending on a per-particle density attribute.

The pattern is similar but lives in driftscope/kernels.py:

def MyPerParticleKernel(particle, fieldset, time):
    # update particle.lon, particle.lat, particle.depth, or any per-particle
    # variable using `particle_dlon`/`particle_dlat`/`particle_ddepth`.
    pass

…and driftscope/simulate.py:380 (kernel chain assembly):

kernels = [AdvectionRK4]
if use_settling: kernels.append(Settling)
if use_brownian: kernels.append(BrownianMotion2D)
if use_my_kernel: kernels.append(MyPerParticleKernel)   # NEW
kernels.append(DeleteOOB)

If your kernel needs per-particle attributes, define a custom particle class (see SedimentParticle at simulate.py:235 for an example) and pass it to ParticleSet.

23.4 Pitfalls

Warning

Time-grid mismatch. Different forcings live on different time grids (daily currents, 6-hourly winds, hourly tides). combine_forcings() already handles this: it picks the finest time grid present and interpolates. Just make sure your fetcher writes a time coordinate that is at least as fine as currents, and combine_forcings will align it.

Warning

Unit consistency. All forcings must produce m/s velocity. If your data source uses cm/s, mm/day, or knots, convert in the fetcher before saving. Past gotcha: pyTMD returns cm/s; tides.py multiplies by 0.01 to get m/s.

Warning

Cache filename collision. The cache filename incorporates all active forcings — __stokes1.0_tides_wind2.0pct_iw.nc. If you forget to add your tag in combine_forcings()’s tag list, two runs with and without your forcing will overwrite the same combined-NetCDF cache and silently produce wrong simulations. Always add the tag.

23.5 Validation

A new forcing is not done until you’ve shown it changes a meaningful answer. Minimum bar:

  1. Smoke test: simulation runs end to end, doesn’t crash.
  2. Quantitative test: with the forcing on vs off, the day-10 particle cloud’s mean position differs by an amount you can predict from the magnitude of your new term.
  3. Drifter test: re-run the validation tutorial; does the LW skill score change in the right direction? If yes, you’re adding signal. If no, you’re adding noise.
  4. Edge case: what happens at the equator? At the antimeridian? In regions with land coverage > 50%?

Each is fast. Skip them and your forcing module will haunt the codebase.

23.6 Summary

  • New forcings follow a fixed four-piece pattern: fetcher, combine clause, SimConfig flag, CLI flag.
  • The pattern is uniform across Stokes, tides, winds — adding the fifth field uses the same shape as the first.
  • Per-particle physics goes in kernels.py, not in fields. Different pattern, but simpler.
  • Validate: smoke test, quantitative test, drifter test, edge case.
