13 Tides — TPXO9 via pyTMD

Chapter 8 explained why tides matter and what harmonic prediction does. This chapter is about the implementation — the TPXO9 model, the pyTMD library that queries it, and the seven gotchas DriftScope navigated when wiring it up.

13.1 TPXO9-atlas-v5

The TPXO project at Oregon State publishes a series of global tide models constrained by altimetry and tide gauges. TPXO9-atlas-v5 is a regionally-refined product that combines:

  • A base 1/6° global grid (TPXO9-atlas).
  • High-resolution 1/30° local grids over major coastlines (including the Bay of Bengal).

The high-res patches stitch into the base grid — when you query a location in a high-res region, you get 1/30° values; outside, you get 1/6°. For the Sundarbans, the local grid resolves the tidal amplification in the delta channels surprisingly well given the simple harmonic representation.

The model has 13 constituents: the major semidiurnals (\(M_2\), \(S_2\), \(N_2\), \(K_2\)), diurnals (\(K_1\), \(O_1\), \(P_1\), \(Q_1\)), long-period (\(M_f\), \(M_m\)), and shallow-water nonlinear terms (\(M_4\), \(M_8\), \(MS_4\)). For deep-water and shelf regions the four largest (\(M_2\), \(S_2\), \(K_1\), \(O_1\)) account for >90% of the tidal variance.

Tip

Why “atlas” and “v5”? The “atlas” refers to the local-grid stitching (it’s a map, not just a global field). “v5” is the model version — each release retunes the inversion against newer altimetry. As of 2026-05, v5 (released 2024) is current.

13.2 How to get TPXO9

The TPXO model is freely distributed but requires registration. Setup:

  1. Register at tpxo.net.
  2. Approval is manual; takes ~24 h.
  3. Download TPXO9-atlas-v5 (NetCDF) from the link in the approval email. ~1 GB.
  4. Unpack to a local directory. Set TIDE_MODEL_DIR in .env to point at it.

DriftScope verifies the path on import:

# driftscope/tides.py:56
def _check_model() -> Path:
    model_dir = os.getenv("TIDE_MODEL_DIR")
    if not model_dir:
        raise RuntimeError("TIDE_MODEL_DIR not set in .env. ...")
    p = Path(model_dir).expanduser()
    if not p.exists():
        raise RuntimeError(f"TIDE_MODEL_DIR points to non-existent path: {p}")
    return p

If you skip TPXO setup, all tide-related calls raise this RuntimeError with a setup hint. The rest of the pipeline (currents, waves, etc.) still works.

13.3 pyTMD — the prediction library

pyTMD is the Python re-implementation of the OSU Matlab tide-prediction routines, maintained by NSIDC. It reads TPXO (and FES, OTIS, GOT) files and predicts tidal currents and heights at any lat/lon/time.

DriftScope wraps pyTMD.compute.tide_currents() in driftscope/tides.py:121:

res = pyTMD.compute.tide_currents(
    xx, yy, tt, component="u",
    directory=str(model_dir),
    model="TPXO9-atlas-v5-nc",
    epoch=(2000, 1, 1, 0, 0, 0),
    type="drift",
    standard="UTC",
    crs=4326,
    method="linear",
    extrapolate=False,
    fill_value=np.nan,
    crop=True,
    bounds=bounds,
    buffer=1.0,
)

13.4 The seven gotchas

pyTMD 3.x has a handful of API quirks that aren’t obviously documented. The seven the project navigated:

  1. Kwargs are case-sensitive in unexpected places. directory= works, Directory= doesn’t.
  2. tide_currents() is the right function name (not tide_velocity or predict_currents). Older docs reference different names.
  3. Model name must include -nc suffix for the NetCDF distribution: "TPXO9-atlas-v5-nc", not "TPXO9-atlas-v5".
  4. directory should be the parent of the unpacked model, not the model dir itself. pyTMD looks for Model_*.txt files in there.
  5. bounds ordering is [xmin, xmax, ymin, ymax], not the more common [lon_min, lat_min, lon_max, lat_max]. Quietly wrong if you mismatch.
  6. The return value is an xarray.DataTree (with branches per component), not a plain Dataset. Convert with .to_dataset().
  7. Output units are cm/s, not m/s. Multiply by 0.01.

That last one is the easiest to forget — DriftScope does it explicitly in tides.py:139:

u_flat = np.nan_to_num(np.asarray(ds.u.values), nan=0.0) * 0.01
v_flat = np.nan_to_num(np.asarray(ds.v.values), nan=0.0) * 0.01
Warning

Don’t filter NaN early. nan_to_num(..., nan=0.0) zeros out land cells. Without this, the combined u_currents + u_tide becomes NaN over land cells where \(u_\text{tide}\) is undefined, and the integrator’s land mask gets confused. We zero land tides; the simulator’s separate land mask removes particles that drift onto land anyway.

13.5 Output schema

driftscope/tides.py:193 writes:

data/tides/<region>_<start>_<end>_tides.nc:
  Variables: u_tide, v_tide        (m/s)
  Coordinates:
    time      hourly (default; configurable via TIDE_DT_HOURS)
    latitude  inherited from currents grid
    longitude inherited from currents grid

The grid is identical to the currents file’s grid. This is by design — the simulation’s combine step doesn’t have to interpolate spatially when adding tides to currents, just temporally.

13.6 How tides change the time grid

When you turn on tides, the simulation’s combined forcing NetCDF is re-gridded onto the tides’ hourly time axis. Daily currents are forward-filled to each hour. See simulate.py:91:

if tides_nc is not None:
    tid = xr.open_dataset(tides_nc)
    time_grid = tid["time"]
    cur_resampled = cur.reindex(time=time_grid, method="nearest")
else:
    time_grid = cur["time"]
    cur_resampled = cur

This is the right thing: M2 has a 12.42-hour period, which would alias horribly on a daily grid. The simulator’s 30-min integration step then samples the hourly tide curve smoothly via linear-in-time interpolation between hours.

Tip

Tide-aware time stepping. Without tides, \(\Delta t = 30\) min is overkill — you could go to 1 h with no loss. With tides on, 30 min is already at the edge of what cleanly resolves M2. Don’t extend \(\Delta t\) beyond 30 min when tides are active.

13.7 Sanity-check the output

Quick visual: pick a point in the bbox and plot \(u_\text{tide}(t)\) for a day:

import xarray as xr
import matplotlib.pyplot as plt

ds = xr.open_dataset("data/tides/sundarbans_delta_2026-04-17_2026-05-01_tides.nc")
ts = ds.u_tide.sel(longitude=89.0, latitude=21.4, method="nearest")
ts.plot()
plt.savefig("tide_check.png")

You should see:

  • A near-pure sinusoid with 12.4-hour period (M2 dominates in the BoB).
  • Spring/neap modulation if you plot >2 weeks.
  • Amplitude 0.3–1.5 m/s depending on location (offshore < shelf < delta channels).

If you see no signal, your TIDE_MODEL_DIR is probably wrong, or crop=True accidentally cropped your bbox out.

13.8 Why not FES or GOT?

pyTMD also supports FES2014 and GOT4.10. They are alternative global tide models constrained by similar altimetry data. For most ocean applications they perform within 5% of TPXO9 in mid-latitudes. We default to TPXO9 because:

  • It has the densest local-grid coverage in the Bay of Bengal.
  • It’s what the Lenain et al. (2026) GOFLOW paper benchmarks against, so cross-comparison with submesoscale work is direct.
  • The 13 constituents are sufficient for shelf work; FES has 34 but the extras are second-order.

You can swap models by changing TIDE_MODEL_NAME in driftscope/config.py:139. The rest of the pipeline doesn’t care.

13.9 Summary

  • TPXO9-atlas-v5 is the default tide model — 1/6° global with 1/30° refinement over coastlines, 13 harmonic constituents.
  • pyTMD does the harmonic prediction; DriftScope wraps it with seven workarounds for API quirks.
  • Output is on the currents grid spatially at hourly cadence; the simulation’s time grid switches to hourly when tides are on.
  • Setup requires a one-time TPXO download (~1 GB) and TIDE_MODEL_DIR in .env.
