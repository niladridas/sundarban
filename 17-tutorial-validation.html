19 Tutorial 3 — Drifter validation

A model is a story until you compare it to data. This tutorial walks through the most informative validation check available for a Lagrangian drift model: simulate a particle from where a real drifter started, overlay the two tracks, compute a skill score.

19.1 The drifter

We use GDP ID 300534064293930 — a NOAA Global Drifter Program drifter that entered the Bay of Bengal from the Andaman Sea in late April 2025 and was tracked for ~6 weeks. Why this drifter:

  • It’s recent enough that CMEMS and HYCOM both have analyses for it.
  • Its track crosses the shelf break and a mesoscale eddy in the eastern BoB — exactly the region where 1/12° models historically struggle.
  • It’s documented in scripts/drifter_validation.py.

19.2 Step 1 — fetch the drifter track

python -m driftscope.drifters \
    --bbox 87,8,95,16 \
    --start 2025-04-20 --end 2025-06-01 \
    --region andaman_to_bob

The fetcher hits NOAA AOML’s ERDDAP server and returns a CSV with hourly positions for any drifter active in the bbox/time window. Output:

data/drifters/andaman_to_bob_2025-04-20_2025-06-01_drifters.csv:
  ID,time,lat,lon
  300534064293930,2025-04-20 00:00:00,8.25,93.10
  300534064293930,2025-04-20 01:00:00,8.27,93.13
  ...

Filter to the one drifter:

import pandas as pd
df = pd.read_csv(
    "data/drifters/andaman_to_bob_2025-04-20_2025-06-01_drifters.csv",
    parse_dates=["time"],
)
drifter = df[df["ID"] == 300534064293930].sort_values("time").reset_index(drop=True)
print(f"{len(drifter)} positions, "
      f"{drifter.time.min()} → {drifter.time.max()}")
print(drifter.head())

19.3 Step 2 — fetch matching currents

We need currents that span the drifter’s actual track. Fetch a wide bbox around the drifter and the time range:

# CMEMS
python -m driftscope.fetch \
    --bbox 87,8,95,16 \
    --start 2025-04-20 --end 2025-06-01 \
    --region andaman_to_bob

# HYCOM (for the A/B comparison)
python -m driftscope.hycom \
    --bbox 87,8,95,16 \
    --start 2025-04-20 --end 2025-06-01 \
    --region andaman_to_bob
Tip

Wide bbox is important. The drifter moved ~600 km over six weeks. If your simulation bbox is too narrow, particles run off the edge and DeleteOOB removes them. Add at least 1° margin in every direction beyond the drifter’s actual range.

19.4 Step 3 — release a particle at the drifter’s start

DriftScope’s typical --seed-lon/--seed-lat/--seed-radius API releases a cloud in a disk. For drifter validation, we want one particle at the drifter’s exact start.

The script scripts/drifter_validation.py does this. Edited highlights:

# scripts/drifter_validation.py (excerpt)
DRIFTER_START_LON = 93.10
DRIFTER_START_LAT = 8.25
DRIFTER_START_TIME = "2025-04-20T00:00:00"

cfg = SimConfig(
    n_particles=1,
    runtime_days=42,        # ~6 weeks
    dt_minutes=30,
    output_minutes=180,
    seed_lon=DRIFTER_START_LON,
    seed_lat=DRIFTER_START_LAT,
    seed_radius_deg=0.001,  # tiny — effectively a point
    include_brownian=False, # deterministic: one trajectory
)

run_simulation(currents_nc, cfg, out_path=out_path)

Run:

python scripts/drifter_validation.py \
    --currents data/currents/andaman_to_bob_2025-04-20_2025-06-01.nc

(or the HYCOM equivalent).

19.5 Step 4 — overlay simulated and real tracks

import xarray as xr
import matplotlib.pyplot as plt
from driftscope.viz import load_trajectories, traj_to_dataframe

# Simulated (CMEMS)
sim = traj_to_dataframe(load_trajectories(
    "data/trajectories/drifter_validation_cmems.zarr"
))
sim_track = sim[sim["traj"] == 0].sort_values("time").reset_index(drop=True)

# Real
drifter = pd.read_csv(
    "data/drifters/andaman_to_bob_2025-04-20_2025-06-01_drifters.csv",
    parse_dates=["time"],
)
drifter = drifter[drifter["ID"] == 300534064293930].sort_values("time")

fig, ax = plt.subplots(figsize=(10, 8))
ax.plot(drifter.lon, drifter.lat, color="black", lw=2,
        label=f"GDP {300534064293930} (real)")
ax.plot(sim_track.lon, sim_track.lat, color="crimson", lw=1.5, ls="--",
        label="DriftScope (CMEMS)")

ax.scatter(drifter.lon.iloc[0], drifter.lat.iloc[0],
           c="green", s=80, marker="*", label="release", zorder=10)
ax.set_xlim(86, 95); ax.set_ylim(8, 16)
ax.legend(); ax.set_title("CMEMS-driven simulation vs GDP drifter")
plt.savefig("data/tutorial3_drifter_overlay.png",
            dpi=150, bbox_inches="tight")

What this looks like in our standing reference run (file in repo):

Look for:

  • First few days: simulation closely tracks real drifter. Initial velocity is well-resolved.
  • Day 7–10: divergence begins. Real drifter loops south-south-east into a mesoscale eddy; CMEMS misses it.
  • Day 22: ~150 km separation. The CMEMS run continues NW; the real drifter is hooked into a sub-mesoscale southward feature.

19.6 Step 5 — Liu–Weisberg skill score

Distance between the two tracks at each time is a metric, but a single-number summary is more useful. We use Liu–Weisberg skill:

\[ S = 1 - \frac{\sum_n \|\mathbf{X}_\text{sim}(t_n) - \mathbf{X}_\text{real}(t_n)\|}{\sum_n \|\mathbf{X}_\text{real}(t_n) - \mathbf{X}_\text{real}(t_0)\|} \tag{19.1}\]

Numerator: cumulative displacement error. Denominator: cumulative displacement of the real drifter from its release point (“how far did it go in total”).

Interpretation:

  • \(S = 1\) — perfect.
  • \(S = 0\) — model has no skill beyond a stationary particle.
  • \(S < 0\) — model is worse than predicting “the drifter doesn’t move”.

For this drifter:

Currents LW skill
CMEMS 1/12° 0.701
HYCOM 1/25° 0.852

The +0.15 improvement is real and has a clear physical interpretation: HYCOM’s higher resolution captures the southward eddy that CMEMS smooths over.

The full implementation is in scripts/drifter_validation_compare.py, which produces a side-by-side plot and the skill table:

python scripts/drifter_validation_compare.py

19.7 Step 6 — what does adding forcings do?

Test the effect of each forcing on the skill score:

# CMEMS + Stokes
python scripts/drifter_validation.py \
    --currents data/currents/andaman_to_bob_2025-04-20_2025-06-01.nc \
    --stokes data/waves/andaman_to_bob_2025-04-20_2025-06-01_waves.nc

# CMEMS + Brownian
python scripts/drifter_validation.py \
    --currents data/currents/andaman_to_bob_2025-04-20_2025-06-01.nc \
    --brownian-kh 100

Typical results in the BoB:

Configuration LW skill Why
CMEMS only 0.701 Baseline; misses sub-mesoscale eddy
CMEMS + Stokes 0.71 Tiny; Stokes is small in this regime
CMEMS + winds (2%) 0.69 Slight worse — windage is wrong for a drogued drifter
CMEMS + Brownian (Kh=100) 0.68 Random scatter doesn’t help one trajectory
CMEMS + tides 0.69 Open-ocean drifter; tides are weak there
HYCOM only 0.85 Resolution is what matters in this case

Two lessons:

  1. Adding more physics doesn’t always raise the score. Each term has a regime where it matters; outside that regime, it’s noise.
  2. Drifters that explore eddy fields reward higher resolution more than they reward more physics. This is the reason DriftScope added HYCOM as a second source.

19.8 Caveats — what this validation does not show

Warning
  • Single-drifter case study, not a fleet-wide statistic. A proper validation runs over dozens of drifters with bootstrapped uncertainty. This tutorial does the smallest version.
  • Drogued drifters track 15-m flow; surface drifters (windage-prone) would score the wind-on configuration differently.
  • Skill scores are bbox-dependent. A short-range track (drifter released near a coast and recovered after a week) is much easier than a long-range track. Don’t compare LW skills across drifters with different durations.

19.9 Try it

Note

Try it — pick a different drifter. Browse https://www.aoml.noaa.gov/phod/dac/dacdata.php for a recent drifter in another region (e.g. Coral Sea, Aleutians, Gulf of Mexico). Adapt the bbox/dates and re-run. Different ocean regimes expose different model strengths and weaknesses; you’ll learn more from three drifters in three regions than from one drifter studied in detail.
