11 Currents — CMEMS and HYCOM

The dominant velocity term in Eq. 1 comes from one of two analyses:

Source Resolution Update Auth DriftScope module
CMEMS GLORYS 1/12° (≈ 8 km) daily, 5-day forecast free signup fetch.py
HYCOM ESPC-D-V02 1/25° lat × 1/12.5° lon daily none hycom.py

This chapter explains why we have two sources, what each delivers, and how they compare in the Bay of Bengal.

11.1 CMEMS: the default

The Copernicus Marine Service’s Global Ocean Physics Analysis and Forecast (GLOBAL_ANALYSISFORECAST_PHY_001_024) is a daily-mean global ocean state estimate at 1/12° horizontal resolution and 50 vertical levels. It is what most operational and academic Lagrangian work uses for surface currents.

Behind the scenes:

  • Model: NEMO ocean model (1/12° ORCA grid).
  • Atmosphere: forced by ECMWF NWP fields (analysis/forecast).
  • Assimilation: SST (multi-sensor L4), altimetry (Jason, Sentinel-3, -6, AltiKa), in-situ T/S profiles (Argo, XBT, gliders).
  • Cadence: hourly hindcast available, daily means most common.

DriftScope uses the daily product. Hourly is available but each day is ~4× larger, and a 14-day BoB region is still ~10 MB at daily. We trade tidal/inertial detail (filtered out in daily averaging) for download speed and simplicity.

Variables we pull:

  • uo, vo — eastward / northward velocity (m/s) at the surface depth level (0.494 m).

The fetcher is one OPeNDAP-equivalent call via copernicusmarine.subset():

# driftscope/fetch.py:74
copernicusmarine.subset(
    dataset_id="cmems_mod_glo_phy-cur_anfc_0.083deg_P1D-m",
    variables=["uo", "vo"],
    minimum_longitude=88.0, maximum_longitude=90.5,
    minimum_latitude=21.0, maximum_latitude=22.8,
    start_datetime="2026-04-17T00:00:00",
    end_datetime="2026-05-01T00:00:00",
    minimum_depth=0.494, maximum_depth=0.494,
    output_filename="...",
)

Output schema:

Dimensions: (time, latitude, longitude)
Variables:
  uo: m/s, surface eastward
  vo: m/s, surface northward
Coordinates:
  time: datetime64[ns], daily 12:00 UTC
  latitude: float32, 1/12° spacing
  longitude: float32, 1/12° spacing
Tip

Why the awkward depth. CMEMS uses fixed depth levels and 0.494 m is the shallowest. It is not exactly the surface — it represents the 0–1 m vertical mean — but it’s close enough that we treat it as surface flow. For a properly surface-trapped tracer (the very top millimeter), you’d want a wave-resolving model, which CMEMS isn’t.

11.2 HYCOM: the second opinion

The Naval Research Laboratory’s HYCOM ESPC-D-V02 (Earth System Prediction Capability, Data, Version 02) is a global HYCOM analysis at 1/25° native resolution, served as 0.04° lat × 0.08° lon. Twice as fine in latitude as CMEMS in the eastern Bay of Bengal.

We added it as a DriftScope source after a drifter-validation episode in April 2026: a real drifter (NOAA GDP ID 300534064293930) entered the BoB from the Andaman side and tracked southwest under what looked like a shelf eddy. The CMEMS-driven simulation missed this feature; the trajectory diverged northward by day 7. Skill score (Liu–Weisberg) on CMEMS: 0.701. Same simulation on HYCOM: 0.852. The eddy was resolved at 1/25° and missed at 1/12°.

The fetch is more involved than CMEMS because HYCOM’s THREDDS server serves daily files (one per variable per day), each ~3 GB globally. We use OPeNDAP byte-range subsetting to pull only the bbox at surface depth, getting ~30 KB per day per variable instead of 3 GB.

driftscope/hycom.py:99:

def fetch_hycom_currents(bbox, start_date, end_date, region_name, force):
    ...
    for day in days:
        u_url = _hycom_url(day, "u3z")     # one file per variable
        v_url = _hycom_url(day, "v3z")
        u = _open_hycom_subset(u_url, "water_u", bbox)
        v = _open_hycom_subset(v_url, "water_v", bbox)
        ...

The output schema is deliberately identical to CMEMS:

Variables: uo, vo
Coordinates: time, latitude, longitude

with the source noted in the file’s attrs["source"]. Anything downstream (simulate, viz, diagnostics) treats them interchangeably.

Warning

Coverage starts 2024-08-10. HYCOM ESPC-D-V02 is a new product. For historical work (pre-2024) you have to use CMEMS. For real-time and recent work, HYCOM is the better choice in the Bay of Bengal.

11.3 A/B: why both?

Two equally-credible sources is a feature, not redundancy. Three reasons:

  1. Validation: comparing the same simulation on both sources tells you what is robust (signals both models agree on) vs model-dependent (signals only one captures). The drifter chapter does this explicitly.
  2. Resolution-limited diagnostics: the dynamics snapshot (Chapter 20) needs the highest-res velocity field available to resolve eddies. HYCOM wins.
  3. Failover: when one source has an outage (HYCOM has weekly maintenance windows; CMEMS has occasional latency), the other usually works.

The drift validation script scripts/drifter_validation_compare.py runs the same simulation on both currents and overlays them on the real drifter for direct visual A/B. This is the most informative single image you can make of “model resolution matters”.

11.4 File-naming convention

DriftScope uses filename suffixes to keep the two sources from colliding:

data/currents/
  sundarbans_delta_2026-04-17_2026-05-01.nc          ← CMEMS (default, no suffix)
  sundarbans_delta_2026-04-17_2026-05-01_hycom.nc    ← HYCOM

This is set in hycom.py:117:

out = CURRENTS_DIR / f"{region_name}_{start_date}_{end_date}_hycom.nc"

So you can fetch both for the same region/window without overwrites, and downstream scripts pick a specific one by name.

11.5 Inside the NetCDF

Open one with xarray to see the schema:

import xarray as xr
ds = xr.open_dataset("data/currents/sundarbans_delta_2026-04-17_2026-05-01_hycom.nc")
print(ds)

Yields something like:

<xarray.Dataset>
Dimensions:    (time: 15, latitude: 44, longitude: 32)
Coordinates:
  * time       (time) datetime64[ns] 2026-04-16T12:00:00 ... 2026-04-30T12:00:00
  * latitude   (latitude) float64 21.0 21.04 21.08 ... 22.64 22.68 22.72
  * longitude  (longitude) float64 88.0 88.08 88.16 ... 90.32 90.4 90.48
    depth      float64 0.0
Data variables:
    uo         (time, latitude, longitude) float32
    vo         (time, latitude, longitude) float32
Attributes:
    source:   HYCOM ESPC-D-V02 (Navy Operational, 1/25° lat × 1/12.5° lon)

A 14-day Sundarbans bbox is 15 time steps × 44 × 32 = 21,120 cells per variable, or about 170 KB total. CMEMS for the same bbox is roughly 15 × 30 × 31 = 14,000 cells — slightly smaller because the 1/12° grid is coarser. Both fit in memory comfortably for any region you’d realistically study.

11.6 Land mask and missing data

CMEMS marks land cells as _FillValue (NaN after xarray decoding). HYCOM does the same. The simulator filters seed points that fall on NaN cells (simulate.py:294) and the DeleteOOB kernel removes any particle that wanders into NaN at run time.

For the Sundarbans the land mask is important — the Sundarbans bbox is ~50% land (mangrove forest). A region-fill (“bbox”) seeding mode oversamples uniformly across the bbox and keeps only ocean cells, giving a coastline-shaped release pattern. This is the right mode for “how does sediment from the whole shelf disperse” questions.

11.7 How to fetch

The CLIs are uniform across both sources:

# CMEMS for a preset region, last 14 days
python -m driftscope.fetch

# CMEMS for a custom bbox / date range
python -m driftscope.fetch --bbox 88,21,90.5,22.8 --start 2024-01-15 --end 2024-02-14

# HYCOM, same region/window
python -m driftscope.hycom --bbox 88,21,90.5,22.8 \
    --start 2025-04-20 --end 2025-06-01 --region "GBM premonsoon"

Both honor cache: re-runs see the file and skip the download. Pass --force to redownload.

11.8 Summary

  • CMEMS GLORYS at 1/12°, daily, is the default surface current source.
  • HYCOM ESPC-D-V02 at 1/25° lat is the second source — finer in latitude, beats CMEMS in BoB drifter validation (LW 0.852 vs 0.701).
  • Both are stored with identical schemas (uo, vo on (time, latitude, longitude)); HYCOM files just carry an _hycom suffix.
  • The drifter-validation script compares the two side by side; the dynamics-snapshot script defaults to HYCOM for the highest-resolution diagnostics.
