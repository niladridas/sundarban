3 Setup

This chapter gets you from a clean machine to “I can run a simulation.” Allow ~15 min if you already have conda; ~30 min from scratch.

3.1 Prerequisites

You need:

  • Python 3.11 via Miniconda or Mambaforge. The project pins parcels, copernicusmarine, and pyTMD versions that don’t always coexist nicely with system Python; conda gives us isolation.
  • Git to clone the repo.
  • About 5 GB of disk for the conda environment, plus 1–2 GB for cached data per region/month you simulate.
  • Free accounts at:
    • Copernicus Marine — for currents (CMEMS) and SST (OSTIA).
    • Climate Data Store — for ERA5 waves and winds.
    • TPXO registration (optional) — if you want tides. Skip if you only care about currents.

3.2 Clone and create the environment

git clone <repo-url> sundarban
cd sundarban
conda env create -f environment.yml      # ~3 min on a warm conda cache
conda activate driftscope

The environment file is at environment.yml. Key pinned packages:

  • parcels >= 3.0 — the Lagrangian framework
  • copernicusmarine >= 2.0 — CMEMS API client
  • cdsapi — ERA5 client
  • pytmd >= 3.0 — tides
  • xarray + netcdf4 + zarr — data plumbing
  • streamlit + pydeck + folium — dashboard
Tip

Why conda not pip? Several of these (parcels, pytmd, rioxarray, cartopy) have C/Fortran extensions whose binary wheels on PyPI lag conda-forge. On Linux pip will mostly work but on macOS/Windows the binary mismatch story is painful enough that we standardize on conda.

3.3 Credentials

Copy the template and fill in the blanks:

cp .env.example .env

.env lives in the project root. It is gitignored; never commit it. The fields you need to fill in are:

Variable Where to get it Used by
COPERNICUSMARINE_USERNAME marine.copernicus.eu signup driftscope.fetch, driftscope.sst, driftscope.chlorophyll
COPERNICUSMARINE_PASSWORD same same
CDSAPI_URL https://cds.climate.copernicus.eu/api driftscope.stokes, driftscope.winds
CDSAPI_KEY CDS profile page → “API key” same
TIDE_MODEL_DIR (optional) unpacked TPXO9-atlas-v5 directory driftscope.tides
Note

The CDS API also accepts credentials via ~/.cdsapirc. If you already have that file from another project, you can leave CDSAPI_* unset — the loader falls back to ~/.cdsapirc. See driftscope/stokes.py:173.

3.4 Smoke test

Verify the environment imports the heavy bits cleanly:

python -c "
import xarray, parcels, copernicusmarine, cdsapi, cartopy
print('xarray', xarray.__version__)
print('parcels', parcels.__version__)
print('cmems', copernicusmarine.__version__)
"

If this prints versions you’re done. If it complains about a missing native library (typically GEOS or PROJ for cartopy), conda update -n driftscope cartopy proj geos usually fixes it.

3.5 Optional: tides

If you want barotropic tidal currents in your simulation:

  1. Register at tpxo.net (free, manual approval, ~24 h).

  2. Download TPXO9-atlas-v5 in NetCDF format (~1 GB).

  3. Unpack to a directory of your choice; set TIDE_MODEL_DIR in .env to point at it.

  4. Verify pyTMD can read it:

    python -c "
import pyTMD.compute, os
print('TPXO at', os.environ['TIDE_MODEL_DIR'])
"
Warning

pyTMD 3.x has API quirks the project works around. If you hit weird errors when calling driftscope.tides, read Chapter 13 for the gotchas and consult the feedback_pytmd_quirks memory.

3.6 Repository layout

sundarban/
├── app.py              # Streamlit dashboard entry point
├── environment.yml     # conda env spec
├── .env.example        # credentials template
├── .env                # YOUR creds (gitignored)
├── README.md
├── driftscope/         # the package — see Chapter [@sec-modules]
├── scripts/            # end-to-end run scripts
│   ├── run_coupled_simulation.py
│   ├── drifter_validation.py
│   ├── drifter_validation_compare.py
│   ├── run_seasonal_dispersion.py
│   ├── plot_coupled_simulation.py
│   ├── spm_apply_sundarbans.py
│   └── sundarban_dynamics_snapshot.py
├── notebooks/          # interactive walkthroughs
├── docs/               # this book
└── data/               # cached data (mostly gitignored)
    ├── currents/  waves/  winds/  tides/  drifters/
    ├── sst/  chlorophyll/  spm/
    └── trajectories/   # zarr outputs from simulate

The data subdirectories are auto-created by driftscope/config.py on import — you don’t need to mkdir anything.

3.7 Where things go

  • Cached downloads → data/<kind>/<region>_<start>_<end>[_provider].nc. The filename encodes the parameters so reruns are idempotent.
  • Simulation outputs → data/trajectories/<stem>.zarr. Zarr is a chunked binary format that xarray reads natively.
  • Figures → data/<descriptive-name>.png (matches existing scripts’ output convention).
