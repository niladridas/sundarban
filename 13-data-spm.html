15 SPM — Sentinel-2 + cluster-based regression

Suspended Particulate Matter (SPM) is the sediment-transport module — Module 7 in the project roadmap. Unlike the forcing modules (Chapter 11 through Chapter 13) which provide velocity fields, and unlike the observation modules (Chapter 14) which provide context for validation, SPM provides initial conditions: “where is the sediment in the water right now?”

The retrieval algorithm is cluster-based regression (CBR), following Geyman & Maloof (2019), who originally developed it for bathymetry on the Great Bahama Bank. We adapt the same structure to SPM concentration in the optically-heterogeneous Ganges-Brahmaputra-Meghna delta.

15.1 What SPM is, optically

Multispectral satellite imagery (Sentinel-2, Landsat) measures water-leaving reflectance at several visible/near-infrared bands. Suspended sediment in the upper few meters scatters light — adds reflectance in the green/red, saturates in the NIR. The observed reflectance vector at each pixel is a function of:

  • SPM concentration (mg/L) — what we want to recover.
  • Phytoplankton chlorophyll — adds green absorption.
  • Colored dissolved organic matter (CDOM) — adds blue absorption.
  • Bottom reflectance in shallow water.
  • Atmospheric residuals in coastal scenes (adjacency to bright land).

In the open ocean, SPM ↔︎ reflectance is monotonic and a single global regression works. In the GBM delta, water types vary radically over a few kilometers:

  • River-plume water: very high SPM (50–500 mg/L), low chlorophyll, high CDOM.
  • Mixing zone: intermediate SPM, mid-CDOM.
  • Shelf-marine: low SPM (<10 mg/L), variable chlorophyll, low CDOM.
  • CDOM-rich tributary: low SPM, very high CDOM (Sundarbans channels).

Each has a different SPM-vs-reflectance shape. A single global fit averages across all four and biases each.

15.2 The CBR idea, step by step

CBR partitions the image spectrally first, then fits a regression per cluster:

  1. Cluster the per-pixel reflectance vectors into \(k\) classes (k-means on the band space, \(k = 4\) for the GBM delta).
  2. For each class, fit a regression SPM($R_1, R_2, …) using matchup data points whose reflectance vectors are near that class centroid.
  3. At inference time on a new pixel, don’t pick one class — compute the spectral distance to every centroid and blend the \(k\) predictions weighted by \(1/d_i\).

The blending step is what makes CBR robust: a pixel exactly between plume and mixing-zone water gets a weighted average of the two class-specific regressions, rather than a hard switch.

Tip

Why not SVM or random forest? Both work, but they lose physical interpretability. CBR’s per-class regression is log-linear in the band ratios, which is the form physical theory predicts (Nechad et al. 2010, semi-analytical SPM). When calibration data are sparse — always the case in remote estuaries — physically structured models extrapolate gracefully where black-box ML over-fits the matchups.

15.3 What’s implemented

The CBR algorithm itself is complete in driftscope/spm.py — pure NumPy + scikit-learn. A smoke test demonstrates CBR successfully recovering two known water-type relationships from synthetic data.

The two upstream pieces are stubbed (not yet wired):

  1. Sentinel-2 fetch: a function that pulls Sentinel-2 L2A reflectance for a bbox/date through Microsoft’s Planetary Computer STAC. The PR is open; needs auth and storage settings.
  2. Matchup ingest: a loader that pulls the AquaMatch v2 TSS measurements (in-situ SPM, 1.4 M observations, US-only) and the matched SiteSR Landsat reflectances. This is a 50 GB download distributed across nine .feather files. Helper at driftscope/aquamatch.py.

The CBR algorithm runs on either source: synthetic data for testing, real matchups for production. Calibration on US estuaries and application to BoB scenes is the transfer-learning pattern — following Tian et al. (2026)’s pan-Arctic SSC work, which calibrated on US sites and applied to Arctic deltas.

15.4 Atmospheric correction

Sentinel-2 L2A products are atmospherically corrected by ESA’s Sen2Cor algorithm. For a quick-look CBR retrieval this is acceptable — the per-class regression absorbs whatever residual atmospheric bias is uniform within a class, since clusters are determined by the data.

For production-grade SPM retrieval — especially in the Sundarbans where mangrove canopy adjacent to dark water creates strong adjacency effects — upgrade to ACOLITE, an aquatic-specialized atmospheric corrector that handles sun glint, aerosol mixtures, and adjacency Vanhellemont & Ruddick (2018). Requires Sentinel-2 L1C (top-of-atmosphere) inputs instead of L2A; adds ~30 min/scene of local processing.

The CBR algorithm doesn’t care which AC was applied — its inputs are just reflectance vectors. Swapping AC pipelines changes the calibration weights but not the algorithm.

15.5 How the SPM map enters a simulation

scripts/run_coupled_simulation.py demonstrates the SPM-weighted release: instead of seeding particles in a uniform disk or basin fill, you sample release locations with probability proportional to local SPM concentration.

# scripts/run_coupled_simulation.py:52
def sample_spm_weighted_seeds(spm_nc, currents_nc, n, rng,
                              min_spm_mg_l=5.0):
    spm = xr.open_dataset(spm_nc).load().spm_mg_l
    cur = xr.open_dataset(currents_nc).load()
    u0 = cur.uo.isel(time=0).squeeze()

    w = spm.values.astype(float)
    valid = np.isfinite(w) & (w > min_spm_mg_l)
    w = np.where(valid, w, 0.0)

    flat_w = w.ravel() / w.sum()
    idx = rng.choice(n_pix, size=n_cand, replace=True, p=flat_w)
    lat_idx, lon_idx = np.unravel_index(idx, w.shape)
    plat = spm.latitude.values[lat_idx]
    plon = spm.longitude.values[lon_idx]
    ...
    return plon, plat

The result: 2000 particles seeded preferentially where the satellite saw sediment, then advected with all forcings (currents + tides + waves + wind + Brownian + settling). The dispersion plot shows where that sediment goes over the next ten days.

Tip

Time-aligned vs representative initial conditions. DriftScope’s demo uses a 2024-03-08 (dry-season) SPM map as the release pattern even when the simulation runs through 2026-04-17 — using the SPM map as a spatial release pattern, not as a time-aligned tracer concentration. For temporally-aligned runs you’d need a Sentinel-2 scene from the simulation start date. Once Module 7’s fetch is wired up, this becomes a one-line change.

15.6 What you’d do as a student

Three Module-7 exercises that pay back the most:

  1. Run CBR on synthetic data to see the algorithm work end-to-end. The smoke test in driftscope/spm.py produces a side-by-side “true vs retrieved” map and an error histogram.
  2. Compute the SPM-weighted release on the existing 2024-03-08 map and run a 10-day simulation with all forcings. Compare the final particle positions with a same-period chlorophyll map — high SPM should track the river-plume signal.
  3. Plug a real matchup dataset in (US sites for now) and check that the per-class regressions recover (Nechad et al., 2010)-style band-ratio shapes — a sanity check that the algorithm is finding the physics, not memorizing the data.

15.7 Summary

  • SPM is a satellite-derived initial-condition map for sediment transport, not a forcing field.
  • The retrieval algorithm is cluster-based regression, suited to optically heterogeneous deltas — a single global regression systematically biases each water type.
  • The CBR algorithm is complete in driftscope/spm.py; the upstream Sentinel-2 fetch and matchup ingest are stubs.
  • Used in the coupled simulation to seed particles where the sediment actually is rather than uniformly.
  • See scripts/spm_apply_sundarbans.py for a worked example.
